# Pose sequence editor

Open `transition-reference-preview.html`. The original player is preserved at `transition-playback-preview.html`. This is an unmerged local art tool, not a game-runtime change.

## Combined brief and implemented workflow

Build an action from a data-driven pose library. Reorder, repeat, replace and append images; drag an occurrence at least 56 CSS pixels beyond the timeline and release to remove it. A closer outside drop cancels. Source poses remain available. Undo/redo and explicit remove/move buttons support experimentation and keyboard/touch use.

Upload individual PNG/WebP/JPEG sprites or grid sheets (up to 64 cells per image). Each nonempty cell receives a stable `upload:<UUID>` pose ID. Preserve source pixels and weapon shape; generate a black alpha silhouette with a light outer contour for reference. Flat edge-background removal is optional. Baked checkerboards, occluded limbs and anatomical reconstruction need an image-generation/cleanup pass: a mask cannot infer hidden anatomy or remove clothing.

Preview the current action with per-occurrence timing, loop/play-once, speed controls, previous-frame overlay and stepping. New poses use a foot estimate and a common floor pivot. Sheet frames share a scale instead of being independently stretched. Move poses in the viewer or adjust X/Y, scale and source-pivot offsets. Placement belongs to each occurrence, so duplicates can differ without changing their source.

Save named action sequences in IndexedDB, autosave the current draft, and export/import portable JSON with uploaded image data. The catalog contains all 160 painted class/outfit images, including menu/detail/portraits, plus 42 combined transition references. IDs remain stable if labels or timeline order change. Greatsword starts with 1 → 3 → 2 → 6 → 5 → 4 → 6 → 7 → 1.

Request 1–3 intermediate poses from any gap. Capture endpoint occurrence IDs, pose IDs, placement and nearby frames at a sequence revision. Export the request with aligned reference images and motion notes. Import returned candidate images (with independent sheet grid controls), review and select them, then accept into the original gap. Changed endpoints or placement block insertion until the gap matches again. The editor does not claim generation is complete when only a request is saved; no remote generation service is connected.

## Data contract

- `catalog.json`: generated by `node art/pose-editor/build-catalog.mjs`; stable reference and painted pose definitions.
- Pose: `id`, `label`, `classId`, `outfit`, `kind`, `src`, dimensions, source `pivot`, shared normalization `scale`.
- Sequence JSON: `schema: "ashenspire.pose-sequence/v1"`, `sequence: {id, name, revision, entries}`, uploaded `poses`, and `requests`.
- Occurrence: independent `entryId`, `poseId`, `durationMs` and `placement: {x,y,scale,pivotX,pivotY}`. Array order is playback order; repetitions are intentional.
- Transition request export: `schema: "ashenspire.transition-request/v1"`, captured request, aligned PNG references and generation prompt.

No upload or saved edit changes repository files automatically. Browser storage is local to the origin (including port). JSON exports are the durable, shareable reference to supply to an agent or copy into project assets. Uploaded content uses embedded raster data; importing external executable URLs is rejected.

## Implementation plan and next production boundary

1. Catalog and stable IDs — implemented for all existing painted poses and transition references.
2. Timeline manipulation and undo/redo — implemented; preserves source assets and repeated occurrences.
3. Upload, silhouettes, registration and playback — implemented; manual correction remains available.
4. Named local saves and JSON roundtrips — implemented, with file/schema/entry validation.
5. Transition request/export/candidate acceptance — implemented; actual generation is an explicit external workflow.
6. Layered game integration and a generation-service adapter — separate work after visual approval. Do not merge the experimental runtime rig.

Browser QA scripts and screenshots are outside the repository in the local temporary `pose-editor-qa` directory. Validation covers pointer reorder/removal thresholds, duplicate/delete/undo/redo, timing/placement, sprite-sheet uploads, JSON and save/reload, request reference export, candidate insertion, playback and mobile layout.
