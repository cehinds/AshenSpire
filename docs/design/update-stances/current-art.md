## Rejected directions and appearance rules

The owner-selected pose package explicitly records the first-pass rejections in [`pose-studio/stances/options-20261008/README.md`](../../../pose-studio/stances/options-20261008/README.md): Reaver's first guard, Rogue's side guard, Starseer's rear book position, and Herald's book orientation. The correction prompts are preserved in `pose-studio/stances/options-20261008/manifest.json` and generation receipts. The corrected intent is a guard that reads forward toward the enemy and books held in front with the open pages facing their reader. In the selected casting poses, Starseer and Herald use viewer-left/anatomical-left book placement; Starseer keeps the staff visibly distinct in the right hand, while Herald's right hand stays free to cast. Do not revive the rejected side-facing Rogue guard or obscure the book/pages behind the caster.

Every existing player stance prompt requires a rear three-quarter view facing right, same character/outfit and class-specific silhouette, full body/feet and full weapon tips, credible anatomy with exactly two arms/two hands, transparent empty surroundings, no scene/floor/glow, and a held readiness pose rather than an action strike. The original source PNGs have dark generation backdrops; transparent RGBA frames are derived exports. The normalized stance package calls the frames flattened paintings and states there is no limb rig. Keep poses distinct by body silhouette and visible equipment at their actual combat display size.

Alternative armor masters reinforce those rules: full cutout, rear three-quarter right, clear alpha around body, no baked floor/UI/outline/aura, preserve each named class/armor palette and its class equipment. Their source review warns that fine embroidery disappears when a figure is about 140 pixels tall; maintain readable class silhouette, dominant weapon and color blocks at that scale. See [`docs/design/class-armor-rear-2026-10-06/REVIEW.txt`](../class-armor-rear-2026-10-06/REVIEW.txt) and `README.txt` in that package.

## Matrix implication and open decisions

Build the visual matrix around the requested weapon/loadout family first, then apply class and armor appearance adapters. Class identity is not a proxy for equipped weapon: the existing selected stances show Reaver with a greatsword, Rogue with paired daggers, Starseer with staff/book, and Herald unarmed/book, while gameplay weapons are swappable. A generic Reaver pose would therefore be wrong for a Reaver currently holding a bow or spear. The current 4×8 action-family library helps as pose reference but still lacks dedicated spear, halberd and unarmed families; the art refs do not resolve those gaps.

The user has clarified the count: 10 options for each weapon group in each of six stance/action families, for 600 base concepts, then appearance adaptations across all four classes. Preserve weapon/loadout correctness when adapting; the 600 are weapon-first identities and class body/outfit adapters are separate. The request also explicitly includes magic versions of stances. Existing selected casting is not a universal magic-pose template: the Reaver's source is hands together, Rogue raises empty hands, and Starseer/Herald use books. Magical treatments should keep both weapon and hand reads unobscured.
