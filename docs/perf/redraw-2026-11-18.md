# Redraw measurements, 2026-11-18

Owner request: "limit the redrawing that happens when upgrading a card, editing a deck, or anything else that influences small changes."

`tools/redraw-probe.mjs` (run: `PLAYWRIGHT_MODULE=<playwright> node tools/redraw-probe.mjs [--only <name>] [--phone]`)
installs a MutationObserver on `document.body` and counts element nodes added and removed (descendants
included) by one action, then checks the list's `scrollTop` and whether a node stamped before the action
(`data-probe-keep`) is still in the document. Desktop 1280x800.

"Container kept = NO" means the stamped node was replaced. A scroll value that goes to 0 means the list lost its position.

## What changed and what is left

- Upgrade picker (`src/ui/components/cardUpgradeModal.js`): the candidate list is built once. A new selection only moves
  the selected marks on the rows (list node, row nodes, focus and scroll stay); the list is rebuilt only when a row's
  own content changes. Choosing another card under an open detail modal retargets that modal (title, (i), faces)
  instead of closing and reopening it. Picking an option marks the radio buttons in place and rebuilds only the
  faces and change rows after them (342 -> 172 nodes). "Select a row" still adds the detail modal itself, which is
  the content the click asks for (the modal shell is 358 nodes, the option cards and faces the rest).
- Deck editor (`src/ui/screens/deckEditor.js`, `src/ui/keyedPatch.js`): `draw()` no longer empties the panel. It builds
  the next tree and patches it against the live one by key (card tile key, deck row instance, pane, list, fold group):
  an unchanged card keeps its node, a kept container takes the new attributes and is patched in turn. Adding or removing
  a card went from 866 added and 866 removed nodes to 215 and 215 (the changed card's tile and row, the counter and the
  inspector); switching pane from 1134 to 166. Selecting the already selected card no longer rebuilds the inspector.
  A card's art well is compared by its place only (it refreshes itself, so a fresh build and the live node differ in
  art state without the card having changed).
- Shop / Blacksmith: switching category already touches 1 node; nothing to change.
- Armoury (`src/ui/screens/equipment.js` `draw()`): NOT changed. It rebuilds through `renderArmouryPanel` and per-view
  layout builders that attach ResizeObservers, hold timers and trays on the nodes they create, so a keyed patch there is
  a larger change than this pass; it already restores the pane scroll. Select a slot row is 321 added / 148 removed.

The scrollTop column reads 30 to 2 or 11 on the deck editor because Playwright scrolls the clicked button into view
before the click (the probe sets 30 px first); the list node itself is the same node, so it keeps whatever the player set.
