# Mobile floor clearance

Only the `mobile` form factor raises the ground layer. Desktop, widescreen and tablet keep their existing scenery geometry. Actor positions, scales and formation cells never depend on this adjustment.

`combatFormationModel.positioning.perspectiveGrid.scene.mobileFloor` authors each ground asset's first full-width painted row (alpha at least 128), normalized to image height. The reviewed mobile ground exports were measured directly; the boundary represents actual terrain rather than the transparent image box. Other regions use their corresponding boundary; missing/custom assets keep their original geometry until a reviewed boundary is authored.

The limit is the top of the back rank's strip (band A) in the empty formation grid for that screen (owner, 2026-10-31 and 2026-11-20). It depends only on the combat box, the zoom, the device and the scene, never on which cells are occupied, how many enemies there are or who is alive, so the backdrop holds still for the whole fight; only a resize refits it. The grid also follows the resting cards' top, which moves with the hand's size, so the stage holds the lines per screen (`HeldBackdropGrid`): a later formation pass on the same screen never replaces them. HUD rectangles are excluded. `src/ui/models/CombatBackdropFitModel.js` builds every input of both combat backdrop fitters, and `tests/combat-backdrop-fixed.test.mjs` checks they match across formations and deaths.

The ground image uniformly scales about its horizontal centre and existing bottom until its painted boundary is at or above that line. Aspect ratio and lower coverage are preserved; the sky, landmarks and SVG camera remain unchanged. Every pass starts from authored layer coordinates, so resize cannot accumulate zoom, and a fit whose inputs are unchanged writes nothing. Ground parallax is held still on mobile to preserve clearance; other scenery motion remains available. The measurement attribute `data-mobile-floor-paint-top` on `.alternative-backdrop` is a physical offset from the combat root top, cleared when inactive.

The mobile player mini HUD uses its existing shared meter and defense badges. HP spans the full inner width with enemy-matched bar thickness and text scale. Defense badges wrap beneath it on the left, while the HP fraction aligns to the right. Tooltips and live values keep their existing behavior; no duplicate HUD state is introduced. This styling follows the selected `mobile` form factor, not a short-window heuristic.

Formation coordinates are field-relative. Conversion to local CSS pixels uses a zero local origin, so a centered display preset does not subtract its outer letterbox offset a second time. This correction preserves unletterboxed geometry. `tests/mobile-centered-formation.browser.mjs` exercises the actual Settings selector and verifies actors and grid cells remain inside the centered game view.

## Centred Mobile preset regression

At 844×390, selecting Settings → Display → Mobile centres the combat root at approximately x332–512. The pre-floor stage at `764743642` subtracted that viewport inset from already-local formation coordinates, placing actors at x20–150. The stage now converts field-relative positions and deltas against a zero local origin; the shared viewport/fixed-element conversion is unchanged. Actor sizes are unchanged. `tests/mobile-centered-formation.browser.mjs` uses the real Settings control and checks actors plus visible grid cells remain inside the centred root.
